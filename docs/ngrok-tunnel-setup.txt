1. OVERVIEW & ARCHITECTURE
================================================================================

ngrok creates secure tunnels from public URLs to your locally running
SentinelMesh services. This allows teammates on different WiFi networks,
cities, or even countries to access your lab environment — without any
port forwarding, firewall changes, or VPN setup.

To serve ALL 5 services through a SINGLE ngrok tunnel (free plan
compatible), we use an nginx reverse proxy in front of the services.
ngrok tunnels into nginx, and nginx routes requests to the right
service based on the URL path.

Architecture:

  Teammate's Browser
        |
        |   https://abc123.ngrok-free.app/
        |   https://abc123.ngrok-free.app/auth/
        |   https://abc123.ngrok-free.app/dashboard/
        v
  ngrok Cloud (single public URL)
        |
        v  (encrypted tunnel)
  nginx Reverse Proxy (port 8080)
        |
        +--> /             -->  Webapp         (port 5000)
        +--> /auth/        -->  AuthService    (port 5001)
        +--> /dashboard/   -->  Grafana        (port 3000)
        |
   [Info endpoints for non-HTTP services]
        +--> /pgadmin      -->  PostgreSQL connection info
        +--> /logs         -->  Log Collector connection info

URL Routing Summary:

  PATH              SERVICE                 TYPE
  ----              -------                 ----
  /                 Webapp                  Full proxy
  /auth/            AuthService             Full proxy
  /dashboard/       Grafana Dashboard       Full proxy
  /pgadmin          PostgreSQL info         JSON info page
  /logs             Log Collector info      JSON info page

The ngrok + proxy services are added as a Docker Compose profile called
"tunnel". They do NOT start with your regular `docker compose up`
command — you must explicitly activate them.

2. PREREQUISITES
================================================================================

  - Docker and Docker Compose installed and running
  - SentinelMesh containers running (docker compose up -d)
  - A free ngrok account (https://ngrok.com)
  - Internet connection on your machine

================================================================================
3. GETTING YOUR NGROK AUTHTOKEN
================================================================================

  Step 1: Go to https://ngrok.com and sign up for a free account.

  Step 2: After logging in, navigate to:
          Dashboard -> Your Authtoken
          Or go directly to: https://dashboard.ngrok.com/get-started/your-authtoken

  Step 3: Copy the authtoken. It looks something like:
          2eXaMpLeT0kEn1234567890abcdef_randomcharshere

  Step 4: Create a .env file in the SentinelMesh project root
          (same folder as docker-compose.yml):

          File: d:\Project\SentinelMesh\.env
          Contents:

              NGROK_AUTHTOKEN=your_token_here

          Replace "your_token_here" with the token you copied.

  IMPORTANT: Never commit the .env file to version control.
             Make sure .env is listed in your .gitignore file.

4. CONFIGURATION
================================================================================

There are two configuration files in services/ngrok/:

  FILE              PURPOSE
  ----              -------
  nginx.conf        Reverse proxy routing rules (path -> service)
  ngrok.yml         ngrok tunnel definition (points to nginx proxy)

  nginx.conf — Reverse Proxy Routes
  ----------------------------------
  The nginx config listens on port 8080 and routes based on URL path:

    location /           -> proxy_pass http://webapp:5000
    location /auth/      -> proxy_pass http://authservice:5001
    location /dashboard/ -> proxy_pass http://dashboard:3000

  Each route sets proper proxy headers (X-Real-IP, X-Forwarded-For,
  X-Forwarded-Proto) so the backend services see the real client info.

  Non-HTTP services (PostgreSQL, Fluentd) have info-only endpoints
  that return JSON with connection details.

  ngrok.yml — Tunnel Definition
  ------------------------------
  Defines a single HTTP tunnel named "sentinelmesh" pointing to the
  nginx proxy on port 8080:

    tunnels:
      sentinelmesh:
        proto: http
        addr: proxy:8080

  This single tunnel serves ALL services. No paid plan required.

================================================================================
5. STARTING THE TUNNELS
================================================================================

  Option A: Start everything (all services + proxy + ngrok)

      docker compose --profile tunnel up -d

  Option B: Start only the tunnel stack (if services are already running)

      docker compose --profile tunnel up -d proxy ngrok

  Option C: Step by step

      docker compose up -d                                  # services
      docker compose --profile tunnel up -d proxy           # proxy
      docker compose --profile tunnel up -d ngrok           # tunnel

  NOTE: The "tunnel" profile ensures ngrok and the proxy do NOT start
        during normal development. You must explicitly opt in.

  VERIFY: After starting, check all containers are running:

      docker compose --profile tunnel ps

      You should see sentinelmesh-proxy and sentinelmesh-ngrok
      alongside the 5 regular services.

================================================================================
6. FINDING YOUR PUBLIC URL
================================================================================

  Since all services go through one tunnel, you only get ONE public URL.

  Method 1: ngrok Web Inspector (recommended)

      Open in your browser: http://localhost:4040

      This shows:
        - The active tunnel URL
        - Live request/response inspection
        - Replay requests for debugging

  Method 2: Docker logs

      docker logs sentinelmesh-ngrok

      Look for a line like:
        t=... lvl=info msg="started tunnel" name=sentinelmesh
              url=https://abcd1234.ngrok-free.app

  Method 3: ngrok API

      PowerShell:
          Invoke-RestMethod http://localhost:4040/api/tunnels

      curl:
          curl http://localhost:4040/api/tunnels

7. SHARING WITH TEAMMATES
================================================================================

  Once the tunnel is running, share the URLs with your teammate.
  Let's say the ngrok URL is: https://abcd1234.ngrok-free.app

  SERVICE             URL TO SHARE
  -------             ------------
  Webapp              https://abcd1234.ngrok-free.app/
  AuthService         https://abcd1234.ngrok-free.app/auth/
  Grafana Dashboard   https://abcd1234.ngrok-free.app/dashboard/
  PostgreSQL info     https://abcd1234.ngrok-free.app/pgadmin
  Log Collector info  https://abcd1234.ngrok-free.app/logs

  Your teammate:
    1. Opens the URL in her browser
    2. On first visit (free plan), she'll see an ngrok interstitial
       page — click "Visit Site" to proceed
    3. She can now use the webapp, authservice, and dashboard normally

  IMPORTANT: The trailing slash matters!
    - /auth/       works (proxied to authservice)
    - /auth        may not work correctly

  IMPORTANT: ngrok URLs change every time you restart the tunnel
             (on the free plan). You will need to share the new URL
             after each restart. Paid plans support fixed subdomains.

  For PostgreSQL access (direct database connection):
    PostgreSQL is a TCP service, not HTTP, so it cannot be fully
    proxied through nginx. If your teammate needs direct database
    access, she has two options:
      1. Connect through the webapp/authservice APIs
      2. Set up a separate ngrok TCP tunnel (requires paid plan):
         docker run -it -e NGROK_AUTHTOKEN=<token> ngrok/ngrok tcp database:5432

8. STOPPING THE TUNNELS
================================================================================

  Stop only ngrok and proxy (keep other services running):

      docker compose --profile tunnel stop ngrok proxy

  Stop and remove tunnel containers:

      docker compose --profile tunnel down

  Stop everything (all services + tunnel):

      docker compose --profile tunnel down

9. TROUBLESHOOTING
================================================================================

  PROBLEM: "NGROK_AUTHTOKEN is not set"
  FIX:     Make sure your .env file exists in the project root and
           contains: NGROK_AUTHTOKEN=your_actual_token
           Then restart: docker compose --profile tunnel up -d

  PROBLEM: ngrok container keeps restarting
  FIX:     Check logs: docker logs sentinelmesh-ngrok
           Common causes:
             - Invalid authtoken
             - Network connectivity issues

  PROBLEM: Teammate sees "502 Bad Gateway"
  FIX:     The target service isn't running or isn't healthy.
           Check: docker compose ps
           Restart if needed: docker compose up -d webapp

  PROBLEM: Teammate sees "Tunnel not found"
  FIX:     The tunnel URL has changed (happens on restart).
           Get the new URL from http://localhost:4040 and share it.

  PROBLEM: /auth/ returns 404 but / works fine
  FIX:     Make sure the trailing slash is included: /auth/ not /auth
           If the authservice app doesn't handle the root path,
           check services/authservice/app.py for route definitions.

  PROBLEM: Grafana shows broken assets at /dashboard/
  FIX:     Grafana may need its root_url configured. Add this env var
           to the dashboard service in docker-compose.yml:
             - GF_SERVER_ROOT_URL=%(protocol)s://%(domain)s/dashboard/
             - GF_SERVER_SERVE_FROM_SUB_PATH=true

  PROBLEM: Slow response times
  FIX:     Traffic goes through ngrok's cloud servers. Some latency
           is expected, especially on the free plan. This is normal
           for a tunneling solution.

  PROBLEM: nginx proxy container won't start
  FIX:     Check logs: docker logs sentinelmesh-proxy
           Common causes:
             - Syntax error in nginx.conf
             - Port 8080 already in use on your machine

10. SECURITY CONSIDERATIONS
================================================================================

  WARNING: SentinelMesh is a VULNERABLE LAB ENVIRONMENT with intentional
  security flaws. Keep the following in mind when using ngrok:

  - ngrok exposes your services to the PUBLIC INTERNET
  - Anyone with the URL can access your services
  - The lab contains SQL injection, weak credentials, and other vulns
  - Only share URLs with trusted teammates
  - Stop tunnels immediately when not in use
  - Never leave tunnels running overnight or unattended
  - Monitor traffic via http://localhost:4040 for unexpected requests

  The "tunnel" profile in docker-compose.yml ensures ngrok never
  starts accidentally — you must always opt in explicitly.
